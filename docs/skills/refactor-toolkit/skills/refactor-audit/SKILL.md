# refactor-audit（代码审计）

> 主动发现重构机会。

## 输入

**项目路径** - 待审计的项目根目录路径。

## 流程

### Step 1: 分析项目结构

**检测项目类型：**

| 配置文件 | 项目类型 | 依赖查看命令 |
|----------|----------|--------------|
| package.json | Node.js | `npm list --depth=0` |
| pyproject.toml | Python | `pip list` |
| requirements.txt | Python | `pip list` |
| go.mod | Go | `go list -m all` |
| Cargo.toml | Rust | `cargo tree` |
| pom.xml | Java | `mvn dependency:list` |

**执行操作：**

1. 使用 **Glob** 扫描目录结构
   - `**/*.{ts,js,tsx,jsx}` - 前端项目
   - `**/*.{py}` - Python 项目
   - `**/*.{go}` - Go 项目
   - `**/*.{rs}` - Rust 项目

2. 使用 **Read** 读取配置文件
   - 识别技术栈版本
   - 提取主要依赖

3. 使用 **Grep** 搜索关键模式：
   - `TODO|FIXME|HACK|XXX` - 技术债标记
   - `console\.log|print\(|log\.Print` - 调试代码残留
   - `any\s*\)` - TypeScript 类型安全问题

### Step 2: 识别代码坏味道

加载 `references/code-smells.md`：

| 坏味道 | 检测方式 | 检测工具 | 严重程度 |
|--------|----------|----------|----------|
| 重复代码 | 同样逻辑出现多次 | Grep 相似代码块 | 高 |
| 过长函数 | 函数超过 50 行 | 代码行数分析 | 高 |
| 过大类 | 类超过 500 行 | 代码行数分析 | 中 |
| 过长参数列表 | 参数超过 4 个 | 函数签名分析 | 中 |
| 发散式变化 | 一个类因多种原因变化 | 变更历史分析 | 高 |
| 霰弹式修改 | 一个变化要改多个类 | 依赖分析 | 高 |

### Step 3: 检查测试覆盖

**查找测试文件：**

| 语言 | 测试文件模式 |
|------|--------------|
| Node.js | `**/*.test.{ts,js}`、`**/*.spec.{ts,js}` |
| Python | `**/*_test.py`、`**/test_*.py` |
| Go | `**/*_test.go` |
| Rust | `**/*_test.rs`、`tests/**/*.rs` |
| Java | `**/*Test.java` |

**执行操作：**

1. 使用 **Glob** 统计测试文件数量
2. 使用 **Grep** 搜索 `describe|it\(|test\(|def test_` 等测试标记
3. 计算测试文件与源文件比例，估算覆盖率

### Step 4: 推荐重构场景

根据发现的代码坏味道推荐重构场景：

| 坏味道 | 推荐场景 | 优先级 |
|--------|----------|--------|
| 重复代码 | 小范围优化（提取方法） | P0 |
| 过长函数 | 小范围优化（提取方法） | P0 |
| 过大类 | 小范围优化（提取类） | P1 |
| 过长参数列表 | 小范围优化（引入参数对象） | P1 |
| 发散式变化 | 小范围优化（提取类） | P1 |
| 霰弹式修改 | 小范围优化（移动方法） | P1 |
| 代码风格不一致 | 代码风格统一 | P0 |
| 技术栈过时 | 技术栈升级 | P1 |
| 框架版本老旧 | 框架迁移 | P2 |

### Step 5: 标注依赖顺序

分析场景之间的依赖关系，建议执行顺序。

**依赖规则：**
- 代码风格统一 → 无依赖，可先执行
- 技术栈升级 → 建议在风格统一后
- 框架迁移 → 建议在技术栈升级后

## 输出格式

```markdown
# 审计报告

## 项目概况
- 技术栈：[...]
- 主要模块：[...]
- 测试覆盖率：XX%

## 发现的问题
| 模块 | 坏味道 | 严重程度 | 影响范围 |
|------|--------|----------|----------|
| ... | ... | ... | ... |

## 推荐重构场景
| # | 场景 | 优先级 | 依赖 | 预计工作量 |
|---|------|--------|------|-----------|
| 1 | 代码风格统一 | P0 | 无 | 小 |
| 2 | 技术栈升级 | P1 | 依赖1 | 中 |
| 3 | 框架迁移 | P2 | 依赖1、2 | 大 |

## 建议
请选择要执行的场景编号，或输入"全部"按顺序执行所有场景。
```

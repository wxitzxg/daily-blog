# 重构检查清单

## 阶段一：代码库理解

### 项目结构
- [ ] 已读取 package.json 了解依赖
- [ ] 已扫描目录结构
- [ ] 已识别主要模块
- [ ] 已理解模块间依赖关系

### 现有规范
- [ ] 已提取命名规范
- [ ] 已提取代码风格
- [ ] 已提取架构模式
- [ ] 已识别现有约定

### 重构范围
- [ ] 已识别可重构模块
- [ ] 已识别不可动模块
- [ ] 已评估重构风险
- [ ] 已确认重构优先级

---

## 阶段二：规划方案

### 计划文档
- [ ] 已创建重构计划文档
- [ ] 已列出所有需要修改的文件
- [ ] 已定义 API 映射表（框架迁移）
- [ ] 已划分 Wave（大规模重构）

### 用户确认
- [ ] 用户已确认重构范围
- [ ] 用户已确认优先级
- [ ] 用户已确认不动的内容

---

## 阶段三：执行重构

### 外科手术式修改
- [ ] 只修改了计划中的文件
- [ ] 没有顺便优化其他代码
- [ ] 保持现有代码风格一致
- [ ] 没有修改计划外的注释

### 测试驱动
- [ ] 修改前已补充测试（如需要）
- [ ] 每次修改后运行测试
- [ ] 所有测试通过

### 代码质量
- [ ] 没有多余的 import
- [ ] 没有多余的变量
- [ ] 没有多余的函数

---

## 阶段四：验证收尾

### 功能验证
- [ ] 所有测试通过
- [ ] 现有功能未破坏
- [ ] 边界情况已处理
- [ ] API 行为一致（框架迁移）

### 代码质量
- [ ] ESLint/Prettier 检查通过
- [ ] 类型检查通过（TypeScript）
- [ ] 无 console.log 残留

### 文档
- [ ] 重构报告已生成
- [ ] 变更记录已保存

---

## 禁止事项检查

- [ ] 没有理解现有代码就动手
- [ ] 没有计划就动手
- [ ] 顺便优化了计划外的代码
- [ ] 修改了与重构无关的注释
- [ ] 添加了用户没有要求的功能
- [ ] 改变了现有 API 的行为
- [ ] 不运行测试就说完成

**以上任何一项违反，必须回退重来。**

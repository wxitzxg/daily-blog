# Google Stitch + DESIGN.md 设计工作流

你的 AI 应用看起来一股"AI 味"？问题不出在 AI 上。

很多开发者用 AI 做过产品或网站，功能都实现了，逻辑也没问题，但打开一看，界面丑得让人不想用。不是 AI 不够聪明，是因为没给它足够的设计规范，它只能靠猜。每次新建一个页面，颜色飘了，字体换了，间距乱了，最后整个产品看起来像十个不同的人做的。

过去解决这问题只有一个方法：花钱请设计师。一套完整的设计稿，少则五六千，多则几万，还要等好几周。现在这套流程可以直接绕开了。

本文将介绍 **Stitch + DESIGN.md + Claude Code** 这套工作流，让你在不到一小时内把项目从"又一个凭感觉编程做的东西"变成专业级产品。

## 1. Google Stitch 是什么

Google Stitch 是 Google Labs 出品的 AI 原生 UI 设计工具，核心是用 Gemini 模型从文字描述、截图、草图直接生成高保真的多页面界面。

### 1.1 核心能力

**完全免费**，不用安装任何东西，浏览器直接打开用。每个月有 350 次标准生成额度，另外还有 50 次实验模式额度，对大多数人来说完全够用。

官网地址：https://stitch.withgoogle.com

Stitch 有几个关键能力：

- **截图重设计**：直接截图扔给它，让它把现有界面重新设计一遍
- **灵感图参考**：把网上找到的灵感图拖进去，告诉它往这个方向走
- **网站风格解析**：粘贴一个网址，它会把网站的设计风格反向解析出来，帮你生成类似风格的界面
- **语音输入**：在画布上直接对着它说你想要什么效果，自动转成 prompt 执行

### 1.2 与传统 AI 编程工具的区别

Stitch 的生成逻辑和普通 AI 编程工具有一个本质区别：**它先生成图片，然后再转成代码**。

这意味着它在视觉设计阶段不受 HTML 和 CSS 的限制，可以"想象"任何东西，然后再往回推着实现。这就是为什么它出来的设计质感，要比直接让 Claude Code 或者 Cursor 画界面好得多。

### 1.3 Vibe Design：用感受描述设计

2026 年 3 月的更新加入了 Vibe Design 概念：不告诉 AI 画什么组件，告诉它你想让用户"感受到什么"。AI 自己决定配色、字体、布局。

比如告诉 Stitch："这是一个温暖、编辑感、值得信赖的产品"，它会自动选择合适的色调、字体和布局风格。这种方式比描述具体参数更能产生有品位的设计。

### 1.4 Stitch 的设计直觉

测试对比发现，**Stitch 强在设计直觉**。给它一段描述，它能快速找到一个有品位的视觉方向，配色、字体、组件风格都想得很到位。

同一提示词多次生成会给出不同风格版本。第一版可能绿色系白底、灵动大方；第二版可能预览有问题需要手动进入编辑状态；第三版可能直接是暗黑风。**设计审美确实在线**，配色体系、版面节奏、留白处理都很舒服，不是那种"安全但无聊"的套路。

两分钟出图，速度也碾压传统流程。

## 2. DESIGN.md 的作用

Stitch 本身只是这套设计工作流的一半。真正让这套流程变得完整的，是一个叫 DESIGN.md 的文件。

### 2.1 DESIGN.md 是什么

**说白了，就是一个普通的 Markdown 文件**。但它里面装的是整套产品的设计语言，包括颜色、字体、组件规范、设计哲学、禁止事项，全部用自然语言写清楚。

如果你用过 Claude Code 做开发，可能对 CLAUDE.md 这个文件不会陌生。它的作用是把编码规范、架构约束、项目约定提前写清楚，这样 AI 每次生成代码都有参照。

DESIGN.md 做的事情完全一样，只不过是把这套模式从「代码层」扩展到了「设计层」。

Google 官方对它的定义是：**一份纯文本设计系统文档，AI Agent 可以读取它来生成一致的用户界面**。没有 Figma 导出，没有 JSON 格式，没有需要安装的特殊工具，就是一个 Markdown 文件。

它不是 Figma 的替代品，**它是设计系统到 AI Coding Agent 之间的桥梁**，让 design-to-code 不再靠猜。

### 2.2 两个文件的分工

VoltAgent 社区对这两个概念的总结非常到位：

- **AGENTS.md 的读者是 Coding Agent**：教它怎么构建项目
- **DESIGN.md 的读者是 Design Agent**：告诉它项目应该长什么样

一个管"怎么做"，一个管"长什么样"，分工非常清晰。

### 2.3 DESIGN.md 的核心内容

Google 官方定义了 4 个核心章节：

**第一章：视觉主题与氛围**
用感受来描述，告诉 AI 这个产品是什么性格或调性。比如"温暖、编辑感、值得信赖"，这是整份文档的精神内核，先定性格再定参数。

**第二章：颜色体系**
每个颜色要有「语义命名 + 用途说明」，不是直接列色值。例如："Terracotta Brand #c96442，用于品牌强调色和 CTA 按钮"。语义名称告诉 AI 什么时候用它，描述性名称只告诉 AI 它长什么样。

**第三章：字体规则**
字体家族、字重、字号、行高、字母间距，关键信息写清楚。除了基础规范，OpenType 的特性开关也很关键。Stripe 的 Sohne 字体在字重 300 配合 ss01 字形替换的时候才有品牌感，如果 AI 不知道这一点，生成的字体效果就是普通的。

**第四章：组件样式**
按钮、卡片、导航、输入框，每类组件的形状、颜色、交互状态用自然语言描述。

### 2.4 扩展章节

VoltAgent 社区仓库将 DESIGN.md 扩展到了 9 个章节，增加了：

- **布局原则**
- **阴影与层次体系**
- **设计禁忌**：特别重要，AI 在没有负面约束的情况下会自作聪明
- **响应式规则**
- **AI 提示词指南**：给出包含具体数值和色值的可执行提示词

### 2.5 设计禁忌的重要性

设计禁忌这一章特别重要。AI 在没有负面约束的情况下会：

- 在不该用品牌色的地方用品牌色
- 混用多种字体
- 在深色背景上用中性灰阴影（根本看不见）

把这些明确写成"不允许"，可以避免大量重复返工。

### 2.6 实用细节

**关于颜色系统**：
颜色命名一定要用语义名称。"Warm Sand"比"浅灰"好，"Terracotta Brand"比"橙色"好。阴影颜色也要纳入色彩体系，Stripe 的阴影是 rgba(50,50,93,0.25) 的蓝调，这本身就是品牌色的延伸，让 AI 知道「阴影也是有品牌的」。

**关于阴影和深度系统**：
深色界面最常翻车的地方就在这里。深色背景上用普通的中性灰阴影完全看不见。Linear 的做法是用半透明白色边框代替阴影，Claude 的做法是用 Ring Shadow 系统（0px 0px 0px 1px 的阴影来模拟比实线更柔和的边框效果）。

**关于圆角**：
圆角不是一个数字，是一套有性格的体系。Stripe 的按钮圆角是 4px，精确、专业、有金融感。Claude 的按钮圆角是 8 到 12px，温暖但不失专业。Linear 的最大圆角可以到 22px，Notion 的胶囊标签直接用 9999px。圆角大小和品牌调性高度相关。

### 2.7 现成的设计规范资源

VoltAgent 的 awesome-design-md 仓库（https://github.com/VoltAgent/awesome-design-md）整理了 6 大类、54 家公司的完整品牌设计规范，包括 Claude、xAI、Cursor、ElevenLabs、Supabase、Vercel、Lovable、Stripe、Notion、Apple、Uber、Airbnb 等。

以 Claude 品牌为例，每家公司的资料包含三份文件：核心 DESIGN.md 设计说明、亮色和暗色两个版本的交互式文件。

风格选择参考：

- 喜欢温暖人文、编辑感、有文学气息的，从 Claude 的 DESIGN.md 开始
- 喜欢极暗极简、工程师审美的，选 Linear
- 喜欢金融感、精密奢华、字体偏轻的，选 Stripe
- 喜欢温暖极简、留白多、消费者产品感的，选 Notion
- 喜欢开发者平台、黑色主题、绿色的，选 Vercel 或者 Supabase

## 3. 组合工作流

现在来说说这整套工作流是怎么跑起来的。

### 3.1 核心公式

**全新工作流 = Stitch + DESIGN.md + Claude Code**

Stitch 当设计总监生成设计系统，DESIGN.md 作为设计语言标准，Claude Code 当前端工程师按规范生成代码。三大工具各司其职。

### 3.2 六步实操流程

**第一步：准备素材**

如果你在改造一个已有的产品，就截图现有界面，直接拖到 Stitch 的画布上。如果是从零开始，就找两三张你觉得方向对的参考图，不需要很多，你要的只是一个大致方向，不是直接 Copy。

**第二步：写一个聚焦的 prompt**

告诉 Stitch 这个产品是干什么的，你想改哪些页面，设计走什么风格，比如暗色系、极简、编辑感之类的。字体方向如果有想法也可以说，标题用衬线体配正文无衬线体，这是一个对大多数 SaaS 产品都挺好用的组合。

**第三步：策展，不是照单全收**

Stitch 会从一个提示词生成多个版本。不要只在画布上看第一个，把它帮你设计的每个版本都翻一遍。可以从一个版本里拿字体，从另一个版本里拿布局，从第三个版本里拿配色。你是在挑和组合，并非被动接受。

**第四步：获取 design.md**

设计完成之后，去右侧面板找「Design Systems」这个功能，点进去，你会看到 Stitch 在你设计的过程中已经自动帮你生成了一套完整的设计系统。字体规范、颜色体系、组件规则、间距标准，全都在里面。最重要的是找到 design.md，把这个文件里的全部内容复制出来。

**第五步：创建 DESIGN.md 文件**

回到你的项目根目录下新建一个文件，就命名为 DESIGN.md，把你刚才复制的内容粘贴进去并保存。**这个文件从现在起就是你整个产品设计语言的唯一标准**。

**第六步：连接 Stitch MCP**

通过 MCP 协议把 Stitch 和 Claude Code 连起来。操作方式是去 Google Stitch 的官方文档搜索"MCP setup"，找到对应你 Coding Agent 的安装命令。

Stitch 官方文档：https://stitch.withgoogle.com/docs/design-md/overview/

针对 Claude Code 的安装命令：

```bash
claude mcp add stitch --transport http https://stitch.googleapis.com/mcp --header "X-Goog-Api-Key: api-key" -s user
```

然后去 Stitch 的 Settings 里的 API 部分生成一个 API Key，把「安装命令 + API Key」一起粘贴给 Claude Code 进行配置。安装并配置完成后建议重启一下 Claude Code 或者重启会话，Stitch 就会显示为已连接。

### 3.3 MCP 连接的价值

DESIGN.md 给了规则，MCP 连接给了更强大的东西——**直接访问 Stitch 画布中实际的 HTML 和 CSS 源码**。

Claude Code 不是从文本描述猜设计，而是读取真实布局代码，理解每个元素的组合方式，然后在你的应用中重建。它甚至会自动加上悬停效果和过渡动画——因为它解读的是真实设计代码。

连接之后，可以直接告诉 Claude Code：

> 按照 Google Stitch 里 dashboard 页面的桌面端框架，用 Stitch MCP 来更新界面。

Claude Code 会自动列出你的 Stitch 项目，找到对应的框架，获取真实的 HTML 和 CSS 源码，然后在你的实际项目里重建这个界面。

### 3.4 四方案对比测试

用同一个中文提示词测试四种方案（给一款叫"墨流 InkFlow"的 AI 写作助手做中文落地页）：

**方案一：Stitch 直接生成**
- 两分钟出图，配色体系、版面节奏、留白处理都很舒服
- 同一提示词三次生成风格完全不同
- 导出只有 HTML/CSS，代码结构比较粗糙

**方案二：Claude Code 裸跑**
- 6 分 20 秒出结果
- 配色偏蓝黑，被"墨流"两个字带跑了
- 对比度低，设计感不强

**方案三：Claude Code + frontend-design skill**
- 4 分 37 秒
- 比裸跑好一些，整体更明亮
- 但提升有限

**方案四：Claude Code + Stitch 的 DESIGN.md**
- 4 分 38 秒
- 字体、排版、色彩层次明显提升
- 四组里视觉效果最好

**结论**：Stitch 导出的 DESIGN.md 比任何 frontend-design skill 的设计指导都具体十倍。Stitch 花两分钟想出来的设计体系，包括完整的视觉主题、颜色命名、字体规则、组件样式，直接丢给 Claude Code 执行效果最佳。

### 3.5 关键注意事项

Stitch 有时候会设计出一些你产品里本没有的功能模块，比如"最近活动"面板或者"通知中心"。让 Claude Code 执行的时候，要明确告诉它哪些功能是实际存在的，哪些该跳过不需要，否则你还得浪费时间删掉那些不该出现的东西。

## 4. 实战案例

### 4.1 一小时完成从设计到上线

设计敲定后，Claude Code 在同一个会话里就能处理剩下的所有事：

**认证模块**
接 Supabase，它帮你设置好用户账户、登录流程和权限安全规则。

**支付系统**
接 Stripe，给它你的公钥和私钥，它自动找到产品 ID，帮你建好结账流程并连接用户系统。记得先用 Stripe 的测试卡 4242 4242 4242 4242 在沙盒模式里验证一遍。

**邮件通知**
接 Resend，密码重置、欢迎邮件、通知消息全部自动接好。

**部署上线**
推到 GitHub 上并部署到 Vercel，一键上线，之后在 Claude Code 里每次改动都会自动同步到线上。

整个过程中 Claude Code 会手把手带你走——你不需要理解 Stripe 的 webhook 或 Supabase 的安全模型，只需要告诉它你想要什么，然后提供对应的凭证。

### 4.2 成本对比

以前要做到专业级设计：
- 设计费：3000 到 10000 美元（约 2 万到 7 万人民币）
- 时间：几周到几个月
- 还需要 Figma 文件转换成代码的时间

现在：
- 一个人，一个下午
- 免费工具（Stitch + Claude Code）
- 一小时完成从设计到上线

独立开发者和小团队第一次有了和融资团队同等的设计能力。

## 5. 诚实说说不足

这套工作流还不完美，需要提前知晓：

**字体问题**：有时候在 Claude Code 应用完 Stitch 的设计之后需要手动调一下。

**颜色精度**：不总是精准复刻，有时候色值会有偏差。

**复杂设计理解**：Stitch MCP 读的是 HTML 和 CSS，所以遇到特别复杂的设计，Claude Code 的理解可能和你在 Stitch 画布上看到的不完全一致。

**Token 消耗**：会话越长，token 消耗越多，成本自然也会上去，所以请保持 prompt 的专注度。

**格式支持**：Stitch 目前还不支持导出 React、Vue 或者 SwiftUI 格式，这几个在 Roadmap 上但还没发布。

**协作功能**：实时协作和多人评论也没有，目前是单用户工具。

**微交互设计**：微交互和动画暂时设计不了，hover 效果和过渡动画有时候是 Claude Code 读取代码之后自己推断加的。

## 6. 总结

过去只有有钱、有团队的公司才能维护一套完整的设计系统，独立开发者或者小团队根本没有这个资源。现在这道门槛基本消失了。

**Stitch 强在设计直觉**，给它一段描述，它能快速找到一个有品位的视觉方向。

**Claude Code 强在工程实现**，给它一份清晰的设计规范，生成的代码结构好、可读性高、浏览器打开就能跑。

**DESIGN.md 是连接两者的桥**。Stitch 把设计决策写成结构化的规范文件，Claude Code 拿着这份规范去写代码。设计归设计，代码归代码，各干各的强项。

虽然这套流程还不完美，但它已经比之前所有的方案都好很多了，而且 Google 在持续快速更新 Stitch，缺口在一直缩小。

可以去试试这套「设计+开发」的工作流新范式，一个人，一个下午，做出以前要花几万块钱和几周时间才能得到的结果。
